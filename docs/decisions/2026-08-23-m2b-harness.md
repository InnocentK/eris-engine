# Engineering decision record — Milestone 2b: end-to-end harness

Date: 2026-08-23 · Branch: `m2b-harness` → `main` · Synthesizer: Claude (Fable 5) · Implementer: Claude, one isolated worktree (two phases, one session-limit interruption with no lost work) · Advisor: Codex via `codex exec -s read-only` (cross-family, block authority)

## Selected approach
The harness becomes runnable end-to-end without an orchestrator:
- **Defect fixes first** (F1–F6): claude budget-trip envelopes keep usage/cost
  (the $0.129-on-$0.10 overshoot is now recorded, not dropped); `invocation_id`
  unique per attempt; OK-with-warning; `BUDGET_TRIPPED` actually produced;
  resume re-hashes blobs; `Stage.VERIFY/SUMMARIZE`.
- **Schema 0.1.3** (EvidencePack, RetryAttempt, ScanResult, SnapshotSanitization,
  ArmRun; field additions) with a new goldens dir + MANIFEST block + pinned
  constant; 0.1.0–0.1.2 byte-identical. `eris.version` 0.3.0; coverage floor 90.
- `retry.py` (classes; unknown = terminal; judge timeout terminal; every attempt
  an event; money ledger with known vs reserved), `cache.py` (content-addressed,
  write-once, hash/pin/scan-verified hits in `cache/`), `sanitize.py`
  (per-worker copy for agy/grok; original never touched; verification on the
  original), `scan.py` (runtime-derived patterns; hashes + counts only),
  `evidence.py` (pack before proposals; evidence_requests loop with refusals
  as events), `stages.py` (frozen prompts; one canonical-JSON DATA section
  between deterministic nonce delimiters; wire models; Eris-assigned ids;
  judge pure-text/no tools), `arms.py` + `ledger.py` (five arms as data;
  paired ablation; STOP/budget; resume), `eval/run.py` (`run`, `campaign`,
  `campaign status`, `--resume`, SIGINT handler only here, exit codes),
  `eval/score.py` (key.json v1; E1 gate; re-scan; exclusions; paired deltas;
  AST guard).

## Dissent and corrections (preserved)
- **Testing critic vs scope:** cache cannot live under `runs/` (one-writer
  rule) → moved to `cache/`; `policy_sha256` in the key breaks pairing across
  policy edits → kept, documented as one-policy-per-campaign; USD ceilings are
  unenforceable for codex/agy → pessimistic per-call reservation.
- **Reliability critic:** found F1–F6 in existing code; argued task-major
  campaign ordering (accepted) and retrying judge timeouts (rejected — E8 hang
  is deterministic; terminal).
- **Architecture vs security on the nonce:** random nonce would break the
  idempotency key → deterministic derived nonce (both agreed once raised).
- **Arm 2 scoring basis:** raw summarizer verdict (enforced also recorded) —
  scoring the enforced verdict would measure Eris, not the baseline.
- **Plan-category gating:** testing critic objected that plan keys are as
  readable as defect keys; user decision (control/plan score normally) stands,
  caveat recorded in EVAL-PLAN.
- **Grok injection:** the architecture planner called it "by assertion"; E1
  had already shown `MANGO PINEAPPLE`; E17 did not reproduce it → "observed
  once, not reproduced"; sanitize anyway.
- **Implementer deviations (accepted):** challenge ids namespaced by critique
  key; `ArmRun.containment` is a policy DECLARATION the scorer gates on
  (verification is M2c); `single` expands to one cell per panel worker; cache
  stores after the run's scan; pgid via an `invocation.spawned` event;
  evidence ids use the executable basename; scan exempts built-in short
  markers from the 12-char floor and drops patterns present in the harness's
  own recorded paths (self-hit).
- **Flakiness root cause (implementer):** macOS `killpg` EPERM on an unreaped
  zombie leaked the worker's pipes; fixed with an EPERM retry + loud refusal
  and pipe closure in `finally`; 4 consecutive clean full runs, plus a 5th by
  the synthesizer.
- **Codex advisor:** see below.

## Unresolved risks
1. E1 containment is a policy declaration; the scorer cannot verify it (user
   decision: accept-and-scan). Scored defect/ABSTAIN arms remain blocked.
2. Cost for codex/agy is reserved pessimistically; real spend is unknown.
3. Relevance of cited evidence is not mechanically checkable (engine checks
   existence/origin/recency only).
4. `arms.py` 87% / `cache.py` 89% coverage: uncovered lines are refusal and
   Windows-absence branches.
5. No live end-to-end run has been performed yet; every path is exercised
   hermetically only. M2c starts with a 1-task plumbing run on a clean
   control snapshot.
