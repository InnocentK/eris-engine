## Operational facts worth keeping

* The session-limit error is UNCLASSIFIED in `retry.py`'s pattern table
  ("unknown: unclassified failure"), so it fell through to `worker.absent` /
  `cell.missing` with a reason string instead of a named class. FOLLOW-UP:
  add a pattern for vendor session/usage limits (terminal-until-reset; a
  timed ceiling, not a transient) with a test.
* A campaign that RUNS TO COMPLETION around a failed cell is FINALIZED -
  `manifest.json` written, resume refused by `RunExists`. The runbook's
  resume instructions cover interrupts DURING a campaign only; a
  post-completion repair is a new campaign. v1's missing measurement (arm
  4's plan-rollout verdict) folds into the next campaign rather than a
  one-cell patch campaign.
* The paired design worked as intended: arm 4 replayed arm 3's proposals in
  every cell (`invocation.reused`), so every computable 4-3 delta is over
  shared proposals; grok emitted one semantically-invalid proposal
  (`claim index out of range`) that the output check caught and one retry
  fixed - MALFORMED_OUTPUT handling observed live, working.
