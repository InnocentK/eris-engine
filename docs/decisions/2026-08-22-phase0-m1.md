# Engineering decision record — Phase 0 Milestone 1 (harness core)

Date: 2026-08-22 · Branch: `phase0-m1` → `main` · Author: synthesizer (Claude, Fable 5) · Implementer: Claude (single isolated worktree) · Advisor: Codex (OpenAI, cross-family, block authority)

## Selected approach

Build ONLY the Phase 0 evaluation-harness core — no orchestrator, state machine,
ledger package, or adjudication loop — as 14 implementation commits + 5 advisor-fix commits on one branch:

- `src/eris/schemas.py` — Pydantic v2 records, `extra="forbid"`, `origin` on every
  record (`model_asserted | mechanically_observed | human_entered`), canonical bytes
  pinned by golden fixtures.
- `src/eris/validate.py` — pure, never-raising adjudication rules (REF_MISSING,
  REF_MODEL_ASSERTED, REF_PREDATES_CLAIM [verification-phase only],
  SUPPORTED_WITHOUT_REFS, DISSENT_EMPTY_WITH_CONTEST, …; `enforce_rulings`
  downgrades and escalates at ≥3).
- `src/eris/policy.py` + `policies/default.yaml` — fail-closed policy; secrets
  refused in YAML; `eris policy pin` writes machine-specific executable hashes to a
  gitignored `pins.yaml`.
- `src/eris/redact.py` — ANSI/C1 strip → folded-view match → base64 rematch →
  `[REDACTED:<pattern>#<n>]` (no fingerprint); exact values from env allowlist AND
  the four credential files on this machine; unparsable declared file fails closed.
- `src/eris/writer.py` — the ONLY path to disk under `runs/`: redact → hash →
  temp+fsync+rename; events with `seq` + `prev_sha256` chain; flock single writer;
  manifest last; only a non-newline partial tail is recoverable on resume.
- `src/eris/launch.py` — per-CLI argv builders with verified read-only flags
  (claude `--safe-mode --permission-mode plan --tools …`, never `--bare`; codex
  `-s read-only --ignore-user-config --ignore-rules -c project_doc_max_bytes=0`;
  gemini/grok plan mode); env built from `{}` with a NEVER list; realpath-pinned
  executable hash checked before spawn; `start_new_session` + SIGTERM → always
  SIGKILL group; stdout/stderr caps; envelope parsers against captured fixtures.
- `src/eris/verify.py` — allowlist GRAMMAR (argv[0] pinned; literal/value flags;
  realpath-contained paths; hard-deny lists verified against captured `--help` of
  the pinned tool versions); `run_allowlisted` re-validates raw argv before spawn.
- `src/eris/snapshot.py` — history-truncated corpus snapshots (mirror → branch →
  `--no-local --depth --single-branch` clone → origin removed); verifier rejects
  every future commit, tree AND blob; real-git integration test.
- `src/eris/doctor.py`, `eval/run.py` — preflight (key NAMES only, redacted probe
  output, never probes a hash-mismatched binary), `--dry-run` (zero spawns),
  single-worker `invoke`.
- Tooling: ruff (+I, format), mypy strict on src, pytest + coverage floor 80,
  pip-audit blocking, pre-commit, CI 3.12/3.14, three autouse hermeticity guards.

## Unresolved risks

1. Workers can READ outside the snapshot (vendor memory stores, the Athena
   working tree, answer keys) — read-only modes restrict writes, not reads.
   Canary-read experiment E1 is mandatory before any corpus run.
2. Gemini CLI is unusable on this machine (auth tier error); the panel currently
   has three lineages (Anthropic, OpenAI, xAI) only if the user accepts Grok.
3. Verification executes repository code (`pytest` imports `conftest.py`);
   `trusted: false` default refuses it; containers are not in scope until Phase 3.
4. `HOME` is passed to CLI workers (required for OAuth) → credential stores
   readable by any worker; mitigated only by exact-value scrubbing.
5. Codex `--json` carries no model id → `model_executed=None`; lineage for Codex is
   policy-declared, not envelope-confirmed.
