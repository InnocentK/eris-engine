```bash
# 3. Launch (SPENDS MONEY; ceilings: per_call 4, per_run 20, per_campaign 200)
.venv/bin/python eval/run.py campaign --corpus eval/corpus --campaign-id v2 \
    --arms indep_verify,indep_verify_critique --repeats 1 \

.venv/bin/python eval/run.py campaign status --campaign-id v2

# 5. Score (read-only); summary lives OUTSIDE runs/ - that directory belongs
#    to RunWriter, and the gate's collision check treats any entry there as
#    a run id
mkdir -p summaries
.venv/bin/python eval/score.py --campaign-dir runs/v2 --corpus eval/corpus \
    > summaries/v2.json
echo "score exit=$?"
```

* To halt mid-flight: use the per-campaign STOP command the PASSING gate
  prints (`touch .../runs/v2/STOP`) - never `runs/STOP`, which stops
  everything.
* To resume after an interrupt DURING the campaign: re-run step 3 with the
  SAME `--arms`, `--repeats` and `--panel` plus `--resume`. Omitting them
  redeclares a different, much larger matrix (`--arms` defaults to all five,
  `--repeats` to 2). A campaign that ran to COMPLETION around a failed cell
  is finalized and cannot be resumed - that repair is a new campaign (v1
  lesson).
* If the gate FAILS on a pin: a worker binary changed since it was last
  authorised. Re-pinning is deliberate: inspect what changed, re-verify the
  new binary behaviourally (precedents: the 2026-09-06/-13/-14 re-pin
  records), then `.venv/bin/python -m eris.cli policy pin --policy
  policies/default.yaml` and re-run the gate.
* If the judge hits a vendor session ceiling mid-campaign it now classifies
  POLICY_TERMINAL (named, terminal); the cell is lost to that campaign - see
  the v1 results record.
